# Phase 3 高速化ガイド

2D イオン輸送シミュレーションは計算負荷が高いため、効率的な実行のためのガイドラインを提供します。

## 高速化の仕組み

### 1. マルチ CPU (Multiprocessing) 対応
CLI の `transport2d compare` コマンドを使用する場合、複数のケースを異なる CPU コアに割り当てて並列実行します。
- **メリット**: 厚みスイープやシード違いの計算を大幅に短縮できます。
- **使用方法**: `transport2d compare` を実行すると、自動的に利用可能な最大コア数が使用されます。

### 2. 行列計算の最適化
- 行列解法には `scipy.sparse.linalg.spsolve` を使用しており、背後では C/C++ で最適化されたライブラリ（OpenBLAS, MKL 等）が動作します。
- 実効物性マップが時間変化しないことを前提に、行列の組み立てを最小限に抑えています。

## パフォーマンスに影響を与える要因

- **格子サイズ (nx, nz)**: ピクセル数に比例して行列サイズが増大します。解像度を 2 倍にすると、行列の要素数は 4 倍、計算時間はそれ以上に増加します。
- **時間刻み (dt)**: 過渡計算のステップ数に直結します。
- **界面面積**: 反応ソース項が適用されるピクセル数が多いほど、右辺ベクトルの更新コストがわずかに増加します。

## 推奨設定

- **初期検討**: 解像度 1.0 um/px, dt=5.0s 程度で全体の傾向を掴むことを推奨します。
- **精密解析**: 解像度 0.2~0.5 um/px で詳細な局所不均一性を確認します。
- **並列実行**: 大規模な比較を行う際は、メモリ使用量に注意してください。1 ケースあたり数百 MB ~ 数 GB のメモリを消費する場合があります。

## 今後の拡張 (GPU 対応)
現在、大規模な行列計算を GPU (CuPy) で加速するための抽象化レイヤーを準備中です。将来のアップデートで、行列演算部を GPU にオフロードすることが可能になります。
