# シミュレーションプログラム Ver1 総合使い方ガイド

本プログラムは、**「技術の確からしさ（知識状態）が実験によって更新されていくプロセス」**を核とし、そこに分散組織特有のコミュニケーションロス（情報の遅延・欠落・誤解）を組み込んだABM/DESハイブリッドシミュレーションです。

## 1. コンセプト：知識状態の更新とコミュニケーション
単なる「成功・失敗」のゲート判定ではなく、以下の要素をモデル化しています。
- **技術要素の状態**: 不確実性、成熟度、証拠量といった多面的な変数が実験ごとに動的に変化します。
- **実験のアウトカム分離**: 「現象としての成否」と「情報としての有効性」を分離。失敗しても技術的理由なら学びが大きく、運用的理由（ミス）なら学びが少ないという現実を再現。
- **情報の劣化**: 組織間の物理的・心理的距離を「遅延」「欠落（データ落ち）」「誤解（条件変質）」として定義。

## 2. 実行方法
以下のコマンドで、設定された全シナリオを連続実行し、レポートを自動生成します。
```bash
cd /Users/koguretaichi/PycharmProjects/DX4MGR/2026/DataAnalysis/Ver1
```

実行後、`reports/` ディレクトリに以下のファイルが生成されます：

- `simulation_report.md`: 実行結果の概要レポート

## 3. パラメータの意味と挙動
設定ファイル：`configs/simulation_params.csv`

### シミュレーション制御
- `scenario_id`: シナリオ名（Distributed, Integrated, LowQualityなど）
- `steps`: シミュレーションを実行する日数（例：500）
- `dr_threshold`: デザインレビュー（DR）へ進むために必要な、全技術要素の累積証拠量（Evidence）の閾値。

### 組織間コミュニケーション特性（各経路ごとに設定）
※経路：`res_proto` (研究→試作), `proto_ana` (試作→解析), `ana_res` (解析→研究)
- `delay_...`: 依頼や結果が相手に届くまでの遅延日数。
- `loss_prob_...`: 情報（メタデータや条件）が欠落する確率。高いと実験の精度（Effective Gain）が低下します。
- `dist_prob_...`: 内容が誤解・変質される確率。高いと「運用的失敗」が増え、解析時に「不確実性の増大（手戻り）」が発生します。

## 4. ロジック解説
### 実験の成否と情報量
- **成功確率**: 技術要素の「成熟度」に比例して上昇。
- **有効情報量 (Effective Gain)**: 実験から得られる「学び」の量。コミュニケーションロス（欠落・誤解）があるほど減衰します。
- **失敗の質**: 
    - **技術的失敗**: 本質的な理由による失敗。有効情報量は比較的維持される（学びがある）。
    - **運用的失敗**: ミスや伝達不足による失敗。有効情報量が激減し、ノイズが増える。

### 統合フェーズ
証拠量が閾値を超えると、バラバラのデータを1つの資料にまとめる「統合（Integration）」が発生します。
- **統合期間**: 組織内で発生した「手戻り回数」や、各技術要素の「文書化度・データ整備度」に依存します。コミュニケーションロスが激しい組織ほど、この期間が指数関数的に増大します。

## 5. 実行結果レポート（サンプル解析）
最新のシミュレーション実行結果に基づいた分析です。

### 指標の比較
- **Integrated（統合組織）**: コミュニケーションロスが最小化されているため、実験1回あたりの有効情報量が高く、運用的失敗が極めて少ない。結果として、DRまでの期間が短く、統合コストも低く抑えられる。
- **Distributed（分散組織）**: 欠落や誤解により「質の悪い失敗（運用的失敗）」が頻発。手戻りが発生し、最終的な資料統合に多くの時間を要する。
- **LowQuality（低品質環境）**: 遅延とミスが重なり、証拠の蓄積が極めて遅い。

### 考察
本Ver1のシミュレーションにより、**「組織の壁が、単に時間を遅らせるだけでなく、実験の質（学びの量）そのものを毀損し、最終的なアウトプット（DR統合）の難易度を跳ね上げる」**というメカニズムが定量的に確認できました。
