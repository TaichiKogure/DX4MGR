# Plan 5x: 統合型意思決定シミュレーションモデル

このプランは、Plan 1からPlan 5までのすべての機能を統合し、より現実的で柔軟なシミュレーションを可能にした究極のモデル（Plan 5x）です。

## 統合された主要機能

### 1. 現実的な開発プロセス (Plan 1)
- **Research → Prototype → Analysis** のフィードバックループを基本モデルとして採用。
- **エージェントベースの学習**: 実験をこなすごとにスキルが向上する学習曲線モデルを搭載。
- **知識の流出**: チーム員の入れ替わり（ターンオーバー）によるスキルの減衰を表現。

### 2. 現実世界の制約と動態 (Plan 2)
- **トレードオフ**: 特定の技術要素を改善すると、副作用として別の要素の不確実性が再燃する動態をモデル化。
- **設備・リソース制約**: 共有設備の故障、修理待ち時間をシミュレーション。
- **知識の風化**: 時間経過とともに情報の確からしさが低下するエントロピーを導入。

### 3. 戦略的実験計画 (Plan 3)
- **ボトルネック優先戦略**: ランダムではなく、不確実性が最も高い（＝リスクが最大）の要素から優先的に着手する戦略を選択可能。
- **統合難易度の動的算出**: 実験証拠の不足量に基づき、DR（デザインレビュー）後の資料統合や調整コストを算出。

### 4. ライフサイクル・フィードバック (Plan 4)
- **TRL Gap (技術成熟度レベルのギャップ)**: プロトタイプで得られた知見が量産移行時に一部通用しなくなる不連続性を表現。
- **市場クレーム KPI**: 市場投入後に残存不確実性が不具合として顕在化するリスクを定量化。

### 5. データ駆動・デジタルツイン (Plan 5)
- **実測ログ連携**: 過去のプロジェクトログ（Jira, ELN等）から、各チームの真の実力値（スキル、エラー率）を自動設定。
- **What-if 解析**: 投資によるスキルアップやプロセスの改善が、最終的な市場クレームやリードタイムにどう影響するかを予測。

## 実行方法
### 1. バッチ実行（複数シナリオの一括シミュレーション）
`Plan5x/` ディレクトリ内で以下のコマンドを実行してください。`configs/simulation_params.csv` に定義された全シナリオを順次実行し、比較レポートを生成します。
```bash
python3 run_sim.py
```

### 2. インタラクティブ実行（GUIによる数値入力と結果表示）
GUI上でパラメータを自由に変更しながらシミュレーションを実行し、その場で結果（数値・グラフ）を確認できます。
```bash
python3 gui_sim.py
```
- **入力**: シミュレーションステップ数、DRしきい値、組織間通信パラメータなどをGUI上で直接編集可能。
- **出力**: 画面上でのKPI表示およびグラフ描画に加え、`reports/gui_results.csv` への保存を選択可能。

## パラメータの柔軟な変更
`configs/simulation_params.csv` を編集することで、以下の設定をシナリオごとに変更できます。
- `strategy`: `strategic` (戦略的) または `random` (ランダム)
- `use_digital_twin`: 過去ログからスキルを読み込むかどうか
- `delay/loss/dist`: 組織間の通信品質パラメータ

## レポートの確認
実行後、`reports/` ディレクトリに以下のファイルが生成されます。
- `simulation_results.csv`: 各シナリオの生データ
- `kpi_comparison.png`: 主要KPI（Gain, リードタイム, 市場不具合）の比較グラフ
- `simulation_report.md`: 分析要約レポート
