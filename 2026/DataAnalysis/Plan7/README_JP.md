# Plan 7: 高度R&D意思決定シミュレーション基盤（最新版 v2 系）

## 概要
Plan 7 は、Plan 6 をベースに「ライブモニタリング」「5 シナリオ比較」「パラメータ比較テーブル」「グラフ解説」「Ver2: 部署/ハンドオフ/会議/リワーク最小実装」を備えた R&D 意思決定支援シミュレーターです。
電池プロセス開発等における、技術成熟度・不確実性、DR（ゲート）運用、リソース制約、組織間ハンドオフの影響を動的に可視化し、投資/配賦判断を支援します。

## 主な新機能

### 1. ライブモニタリング (リアルタイム進捗 + 段階的グラフ更新)
シミュレーションの実行状況として、Scenario A/B/C/D/F ごとの経過時間とCPU/メモリ使用率をライブ表示します（進捗バーは簡素化のため廃止）。
グラフ更新はGUIが固まりにくいよう段階的に間引いて反映されるため、長期間シミュレーションでも進捗テキストとステータスを継続的に確認できます。

### 2. 5シナリオ比較モード（ABCDF）
「Scenario A」「Scenario B」「Scenario C」「Scenario D」「Scenario F」の5つの設定セットを同時に管理し、並行してシミュレーションを実行、結果を並べて比較できます。
戦略やリソース配分の違いが、最終的な利益や開発期間に与える影響を多角的に分析可能です。

### 3. パラメータ比較テーブル
全パラメータを一つのテーブルで管理。3つのシナリオで異なる値を横並びで比較し、上下ボタン（スピンボックス）やキーボード入力で直感的に変更できます。

### 4. グラフ解説・意思決定支援
各グラフの意味、見方、およびシミュレーション上の考え方をGUI内で確認できる「グラフ解説」タブを搭載。R&D戦略立案のヒントを提供します。

### 5. 設定ファイルのインポート/エクスポート
GUIで微調整した3シナリオ分のパラメータをJSONファイルとして一括保存・読み込み可能です。
特定のケーススタディ設定をチームで共有したり、以前の設定を瞬時に復元したりできます。

### 5. 豊富な可視化バリエーション
最新のアップデートにより、以下のグラフがダッシュボードに追加されました：
- **リソース稼働率推移**: 各工程（研究・試作・量産）のサーバーがどれだけ稼働しているかを時系列で表示。
- **リードタイム詳細内訳**: 平均リードタイムを「実作業」「待ち時間」「判定待ち」に分解してスタック棒グラフで表示。
- **累積コストトレンド**: ゲート（DR）審査等に伴う累積費用の推移を可視化。
- **WIP/負荷ヒートマップ**: 各工程の仕掛品（WIP）の偏りを一目で把握。

## 実行方法
以下のコマンドで GUI ダッシュボードを起動します（プロジェクトのルートから実行可能）。
```bash
python 2026\DataAnalysis\Plan7\gui_sim.py
```

オプション（GUI 内）:
- 5 シナリオ（A/B/C/D/F）を個別に編集・保存・読み込み
- グラフの表示/非表示切り替え、更新間引き（描画負荷の低減）
- シナリオ A/B/C/D/F の実行有無をチェックボックスで選択して実行（任意の組合せが可能）
- 3D 動画の回転 ON/OFF と視点（elev/azim）の任意指定が可能
- 3D デザイン（各グラフごとにプルダウンで選択）: Default / Dark / Publication / Wireframe / HighContrast / Monochrome
 - 動画/3D オプションの「配置」切替（自動/横並び/縦並び）に対応（画面幅が狭い場合でもオプションがダッシュボードに隠れません）
 - グラフデザイン（全体テーマ）の切替: フォント/カラーパレット/スタイルをコンボボックスから選択可能（選択直後に全グラフへ反映）

### DOE（パラメータ感度）実行とレポート出力（Plan7 専用）
Plan7 用の DOE ランナーを用意しています。中間データのサマリを含む CSV/PNG/Markdown を一括生成します。

例:
```bash
python 2026\DataAnalysis\Plan7\experiments\plan7_doe.py --steps 180 --seeds 2 --outdir 2026\DataAnalysis\Plan7\reports\doe
```

オプション:
- `--config`: JSON でパラメータグリッド/ベース値を指定（未指定時はデフォルト）
- `--steps`: 1試行あたりのステップ数の上書き
- `--seeds`: 各グリッド点での乱数シード数

出力先（例）:
- `2026/DataAnalysis/Plan7/reports/doe/<日時>/runs.csv`
- `2026/DataAnalysis/Plan7/reports/doe/<日時>/summary_main_effects.csv`
- `2026/DataAnalysis/Plan7/reports/doe/<日時>/plots/*.png`
- `2026/DataAnalysis/Plan7/reports/doe/<日時>/DOE_Report.md`

注意: プロジェクト直下の `reports\doe` は旧版の一時出力場所です。Plan7 以降は `2026\DataAnalysis\Plan7\reports\doe` のみを使用します（本リポジトリでは旧 DOE データを削除済み）。

## ディレクトリ構成

- `configs/`: デフォルト設定ファイル (JSON, CSV)

## GUI の選択が SIM 結果に与える影響（重要）
GUI での主な選択肢と、SIM 指標（KPI/メトリクス）への影響の関係を要約します。

- 実験戦略 `strategy`（`strategic`/`random`）
  - strategic: 研究→不確実性が高い対象を優先、試作→不確実性が一定以下の中で成熟度の低い対象を優先。成功確率と学習効率が上がりやすく、同一リソースでのスループット向上、LT 短縮、失敗率低下が期待できます。
  - random: 対象選択がランダム化。局所最適が抑制される一方、成功率/効率が下がり、やや LT/コストが悪化しがちです。

- デジタルツイン `use_digital_twin`（ON/OFF）
  - ON: 過去ログ（`past_logs_file`）からのキャリブレーションにより、初期の行動や閾値調整が入り、立ち上がり効率が改善（初期失敗・リワークの抑制）。
  - OFF: 完全な素の挙動。初期段階での試行錯誤が増え、短期 LT/コストが悪化する場合があります。

- リソース並列度 `res_n_servers` / `proto_n_servers` / `mass_n_servers`
  - 値を増やすと各工程の並列処理が増え、ボトルネック工程の WIP が低下しやすく、スループットが向上。過大増強はアイドル率上昇→コスト効率悪化の可能性。

- WIP 制限 `wip_limit_res` / `wip_limit_proto`
  - 低すぎる: スループット低下。高すぎる: 待ちが増えて LT 悪化。DOE で適正値を探索します。

- DR 閾値 `dr*_matur_limit`/`dr1_uncert_limit` と会議周期 `dr1_period`
  - 閾値を厳しく/会議を疎に: 合格率低下・判定待ち増で LT/コスト悪化、リワーク増。
  - 閾値を緩く/会議を密に: 初期通過は増えるが、後工程の不具合/リワークが増えやすい。総合最適は DOE 推奨。

- 部署を考慮 `consider_departments`（ON/OFF）
  - ON: 部署の `SLA.max_wait` を超える待機が発生すると `sla_violations` KPI がカウントされます。処理時間×部署 `cost_factor` が `dept_cost_time` に積み上がり、累積コスト（可視化）も増えます。結果として、待機の偏りが LT/コストに敏感になります。
  - OFF: 部署 SLA/コスト係数は無視され、待機→KPI 影響は軽くなります。

- ハンドオフを考慮 `consider_handoffs`（ON/OFF）
  - ON: 異部署間遷移で、ハンドオフ分布（`transfer_time_dist`）に応じた追加遅延が加算。`q_if`（IF 品質）と `info_loss_lambda`（情報損失）により、実験プロトコル準拠度が低下→失敗/リワーク増のリスク。`handoff_events` KPI が増加します。
  - OFF: ハンドオフ遅延/品質低下を無視します。

- 横断会議を考慮 `consider_cross_meetings`（最小スタブ）
  - 現行 v2 では保持のみ（将来拡張）。可視 KPI への直接影響は限定的です（レポートには参加部署や閾値が注記されます）。

- リワーク規則を考慮 `consider_rework_rules`（最小スタブ）
  - 現行 v2 では WorkItem 仕様の保持が中心。主要な再作業フローは DES 側の `ReworkPolicy` により制御されます（`rework_load_factor`/`max_rework_cycles`/`decay`）。極端な値はリワーク頻度・負荷（LT/コスト）に直結します。

上記の選択は可視化（WIP/負荷ヒートマップ、LT 内訳、累積コスト、ゲート待機）に反映されます。特に `consider_departments` と `consider_handoffs` を ON にすると、待機起因のロス時間とコスト上昇が顕在化し、DR 前後のボトルネックが見つけやすくなります。

## 動画/3D 出力について
- GUIの「詳細レポート出力」で「動画も生成（3D/2D）」にチェックを入れると、以下の3D可視化を選択して静止画/動画を自動生成できます。
  - 3D WIPサーフェス（時間×工程/部署×WIP量）
  - 3D リードタイム分解（作業/待機/判定待ちの平均を簡易サーフェス化）
  - 3D 技術成熟の拡散（時間×成熟度×不確実性の3D折線）
  - 立体ネットワーク図（部署間の関係を円配置で立体表示・最小実装）
- 生成の詳細オプション:
  - 「フレーム間引き」: アニメーションのフレームを間引いて軽量化（1/2/3/5/10）。
  - 「回転」: 回転の有無を切替（ON/OFF）。回転 OFF の場合は固定視点でレンダリング。
  - 「視点（elev/azim）」: 表示角度（仰角 elev、方位角 azim）を任意指定。回転 ON の場合は指定角度を基準に回転開始。
  - 「3Dデザイン（各種）」: 可視化ごとに見栄えをプリセットから選択できます。
    - WIP/LTサーフェス: `Default`（標準）, `Publication`（論文向け配色/輪郭）, `Wireframe`（ワイヤーフレーム）, `HighContrast`, `Monochrome` など
    - 技術拡散(3D折線): `Default`/`Dark`/`HighContrast` ほか（カラーパレット/背景が切替）
    - ネットワーク3D: 背景/ノード色/軸表示有無などがプリセットで切替
- 保存先（Plan7配下）:
  - 静止画: `2026/DataAnalysis/Plan7/reports/viz/<SCENARIO_ID>_<種別>.png`
  - 動画: `2026/DataAnalysis/Plan7/reports/viz/videos/<SCENARIO_ID>_<種別>.mp4`
    - 種別例: `wip_3d`, `leadtime_3d`, `tech_diff3d`, `network3d`
- 環境に `ffmpeg` が無い場合は、動画は `.gif` に自動フォールバックします（例: `<SCENARIO_ID>_wip_3d.gif`）。

### レイアウトと視認性（Plan7 v2.4 以降）
- 左ペイン下部の「動画/3D 出力オプション」は、配置コンボ（自動/横並び/縦並び）で切替できます。
  - デフォルトの「自動」では、ウィンドウ幅が狭いときに自動で縦配置へフォールバックし、ダッシュボードと重なって隠れないように調整します。
  - 横並びでは従来と同様に1行に収め、縦並びでは「動画生成」「3D出力」「フレーム間引き」「回転/視点」「3Dデザイン」を順に縦に積み上げます（3D出力の各チェックは縦に展開）。
 - ウィンドウが小さい場合に備えて、左パラメータテーブルと右ダッシュボードの両方で水平スクロールバーを追加（Shift+マウスホイールで横スクロールも可能）。

### 進捗表示の簡素化
- ステータス欄の進捗バーを廃止し、「使用メモリ量（%）」と各シナリオの「経過時間（秒）」のみを表示します。

## Ver2: 部署/ハンドオフ/会議/リワーク規則の拡張（最小実装）
- GUIパラメータに以下のトグルを追加しました（デフォルトON: 部署/ハンドオフ、OFF: 横断会議）。
  - 「部署を考慮」: 部署のSLA（最大待機）とコスト係数を考慮。SLA違反件数や部署コスト時間をKPIに計上。
  - 「ハンドオフを考慮」: 部署間のインターフェース品質(q_if)・情報損失率(λ)・転送/待機時間分布を考慮（最小）。
  - 「横断会議を考慮」: 部署横断会議の間隔・閾値・意思決定ロジック（GO/COND/NO_GO）スタブを保持（今後拡張）。
  - 「リワーク規則を考慮」: AND/OR結合や差し戻し規則の保持（今後拡張）。

- 入力が無い場合でも、上記トグルが ON なら最小の部署/ハンドオフ設定を自動生成して動作します（R, P, A, M）。
- 詳細レポート出力時に、以下の関連アセットを追加保存します。
  - `*_dept_network.png`: 部署/ネットワークの簡易図（最小版、既存ネットワーク3Dの静止画を流用）。
  - `*_dept_summary.csv`: KPI由来の`SLA違反件数`、`ハンドオフ回数`、`部署コスト時間`のサマリ。
