# Plan 4: プロセススコープの拡大（バリューチェーン統合）

このプランでは、研究・開発単体ではなく、量産試作から市場フィードバックまでを繋げたバリューチェーン全体のシミュレーションをモデル化しています。

## 追加された主要機能

### 1. 量産移行とTRLギャップ（TRL Gap）
デザインレビュー（DR）通過後、開発から量産（Mass Production）への移行プロセスを導入しました。
- **技術成熟度（TRL）の壁**: 試作（Prototype）段階で「確からしい」とされた証拠も、量産環境ではその有効性が低下（証拠量の減衰）し、不確実性が再燃します。
- これにより、開発終盤での「想定外の手戻り」を表現します。

### 2. 市場フィードバックループ（Market Feedback）
量産開始後の「市場での不具合」を、不確実性の急上昇としてR&Dへ戻すフィードバックパスを実装しました。
- **市場クレーム（Market Complaints）**: 開発段階で不確実性を十分に下げきれなかった要素が、市場投入後にトラブルとして露呈します。
- これにより、単なる「DR通過」がゴールではなく、市場での安定稼働までを見据えた開発の重要性を可視化します。

### 3. 量産チーム（MassProduction）の導入
開発チームとは異なる制約条件（WIP制限やコミュロス設定）を持つ量産チームを組織ネットワークに追加しました。

## シミュレーションの実行
`Plan4/` ディレクトリ内で以下のコマンドを実行してください。
```bash
python3 run_sim.py
```

## 観測ポイント
- DRを通過しても、量産移行時に `uncertainty` が再度上昇するため、最終的な完成（全要素の不確実性解消）までには追加の時間がかかります。
- KPIに `market_complaints`（市場クレーム数）が追加され、開発時の「証拠の質」が将来の品質コストにどう直結するかが観察できます。
- 「開発リードタイムの短縮」と「市場品質」の間のトレードオフを議論するための材料となります。
