# Plan 2: 動的な環境と不確実性の深化（リアリティの追求）

このプランでは、技術要素間の依存関係（トレードオフ）や、設備故障、時間の経過による知識の風化など、より現実的な外部要因をモデルに導入しています。

## 追加された主要機能

### 1. 技術間のトレードオフ（Trade-offs）
ある技術要素の不確実性を下げると、別の要素の不確実性が上昇する依存関係を定義できます。
- **例**: 「材料配合（Material Mix）」の最適化を進めて極端な条件に振ると、「プロセス条件（Process Conditions）」の制御が難しくなり、その不確実性が再燃する。
- これにより、「あちらを立てればこちらが立たず」という開発現場の難しさを再現します。

### 2. 不確実性の再燃（Knowledge Decay）
時間の経過とともに、過去に得られた知見の「確からしさ」が微減します。
- 放置された技術要素は、周辺状況の変化や記憶の曖昧化により、不確実性が少しずつ上昇します。
- 継続的な実験やメンテナンスの重要性を定量化できます。

### 3. 設備故障と外乱（Resource Failure）
実験設備（Resource）に故障率と修理時間を導入しました。
- **設備故障**: 実験中に設備が故障すると、その回は「設備故障による失敗」となり、情報は得られません。
- DES（離散事象シミュレーション）的なリソース待ち行列の詰まりを表現する基礎となります。

## シミュレーションの実行
`Plan2/` ディレクトリ内で以下のコマンドを実行してください。
```bash
python3 run_sim.py
```

## 観測ポイント
- トレードオフ設定により、一つの要素が完璧になっても全体の不確実性がなかなか下がらない「足踏み状態」が発生しやすくなります。
- 設備故障が発生すると、実験回数は増えても有効な情報量（total_gain）が伸び悩み、リードタイムが長期化します。
- 不確実性の再燃により、DR（デザインレビュー）のしきい値に到達する直前で足踏みするような挙動が見られる場合があります。
