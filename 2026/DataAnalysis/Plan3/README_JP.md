# Plan 3: 意思決定とリソース最適化（戦略的アプローチ）

このプランでは、「どの実験を優先すべきか」という戦略的なタスク選択ロジックと、デザインレビュー（DR）のタイミングがプロジェクト全体に与える影響をモデル化しています。

## 追加された主要機能

### 1. 戦略的タスク選択（Strategic Task Selection）
従来のランダムな実験対象の選択から、現在の技術要素の状態に基づいた動的な選択ロジックを導入しました。
- **不確実性優先（Uncertainty-driven）**: 現時点で最も不確実性が高く、ボトルネックとなっている技術要素を自動的に特定し、重点的にリソース（実験スロット）を投入します。
- これにより、場当たり的な実験を減らし、最短ルートでの証拠（Evidence）蓄積を目指します。

### 2. DR時期の最適化とコスト比較（DR Timing Optimization）
DR（デザインレビュー）を実施するタイミングのしきい値を変化させ、その後の「統合コスト」とのトレードオフを評価できます。
- **強行DR（Early DR）**: 証拠が不十分な状態でDRを強行すると、統合資料作成時に「矛盾の露呈」や「説明不足」が発生し、統合日数（integration_days）が跳ね上がります。
- **慎重DR（Late DR）**: 証拠を十分に溜めてからDRを行うと、統合はスムーズに進みますが、そこに至るまでの実験期間が長くなります。

### 3. 情報利得の予測（Implicit Info Gain Prediction）
エージェントが「どの実験を行えば最も不確実性が下がるか」を暗黙的に判断する設定を導入しています。

## シミュレーションの実行
`Plan3/` ディレクトリ内で以下のコマンドを実行してください。
```bash
python3 run_sim.py
```

## 観測ポイント
- `Strategic` シナリオは `Random` シナリオに比べ、同じ実験回数でも効率的に不確実性が低下することを確認できます。
- `EarlyDR`（しきい値が低い設定）では、実験期間は短縮されますが、KPIの `integration_days` が増大し、トータルのリードタイムが逆に伸びる「急がば回れ」の現象が観察されます。
- 最適な `dr_threshold` を見つけるための感度分析のベースとして活用可能です。
