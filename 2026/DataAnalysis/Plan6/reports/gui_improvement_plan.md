# GUI 主体シミュレーションソフトウェアへの改善プラン

## 1. 現状の課題
現在の `gui_sim.py` は以下の課題を抱えています：
- **設定項目の不足**: 実験周期（Period）やリソース数などの主要パラメータしか変更できず、詳細な設定（分布、承認者、技術閾値等）ができない。
- **可視化の限定性**: シミュレーション終了後の結果（Gain, WIP等）が数値として表示されるのみで、プロセスの動的な進捗が視覚的に分かりにくい。
- **DOE（実験計画法）との連携不足**: GUIから一括で複数のパラメータテストを実行し、結果を比較する機能がない。

## 2. GUI改善に向けた3段階の拡張プラン

### ステップ 1：詳細パラメータ設定タブの実装
- **構成**: 設定パネルを「基本設定」「リソース設定」「技術/ゲート設定」のタブに分割。
- **追加項目**:
    - 各フェーズ（Research, Prototype, Mass Production）ごとのエンジニア数（`n_servers`）スライダー。
    - 各ゲートの通過閾値（`uncertainty_threshold`, `maturity_threshold`）設定。
    - 暗黙知度（`tacitness`）や学習係数（`learning_rate`）の調整。

### ステップ 2：リアルタイム進捗の可視化
- **ダッシュボード化**: 実行中に以下のグラフをリアルタイムで更新。
    - **技術ポートフォリオ図**: 技術要素の「不確実性 × 成熟度」プロット。点が右下に移動する（成熟度アップ・不確実性ダウン）様子をアニメーション。
    - **WIP履歴曲線**: 各ノードの仕掛かりジョブ数の推移。
    - **フェーズ進捗バー**: 全体のプロジェクトが現在どのフェーズに集中しているか。
- **ログモニター**: ゲートでの判定結果（GO / REWORK）を逐次表示。

### ステップ 3：DOE実行・分析機能の統合
- **DOE一括実行ボタン**: GUI上で指定した範囲のパラメータから自動で100回実行する機能。
- **比較・分析**: 実行後に「どのパラメータが最も Gain に寄与したか」を、DOEサマリーレポートのようにグラフで表示。
- **シナリオ保存・読み込み**: 成功したパラメータセットを JSON ファイルとして保存し、再利用可能にする。

## 3. 推奨技術スタックと構成
- **フロントエンド**: `CustomTkinter` (現在の Tkinter をモダンにする) または `PyQt6` (より高度な UI 設計が可能)。
- **グラフ描画**: `Matplotlib` の `FigureCanvasTkAgg` を利用して GUI 内にグラフを埋め込む。
- **非同期処理**: シミュレーション実行中に GUI がフリーズしないよう、`threading` または `asyncio` を使用したバックグラウンド実行を導入。

## 4. 改善のロードマップ
1. **短期 (1ヶ月)**: `gui_sim.py` の入力項目を `Simulation.setup_with_params` の全引数に対応させる。
2. **中期 (2ヶ月)**: リアルタイムグラフ（技術ポートフォリオ）を追加。
3. **長期 (3ヶ月)**: DOE実行・感度分析結果の視覚的表示機能を統合。
