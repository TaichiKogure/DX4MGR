# Plan 6: Hybrid R&D Decision Simulation Model (Integrated Plan 5x & Ver 14)

このプランは、Plan 5x（技術動態・組織・スキル・通信・デジタルツイン）と Ver 14（離散事象シミュレーション・ゲート承認・リソース制約・リワーク）を高度に統合した、R&Dマネジメント向けの次世代意思決定シミュレーションモデルです。

## 統合された主要機能

### 1. ハイブリッド・シミュレーションエンジン (Plan 6 Hybrid)
- **DES (Discrete Event Simulation)**: Ver 14の離散事象エンジンをベースに、リソース（エンジニア数）制約やDR（デザインレビュー）の周期的な開催をモデル化。
- **動的ノード生成**: JSON/YAML設定ファイルに基づき、Research, Prototype等の工程（ゲート）を自由に定義可能。
- **多段プロセスフロー**: 各フェーズを通過するために特定の技術閾値（不確実性や成熟度）を要求。
- **技術動態更新**: 各Job（プロジェクト）がWorkGateを通過する際、Plan 5xのロジックに基づいて技術成熟度（Maturity）が向上し、不確実性（Uncertainty）が減少。

### 2. 可視化・分析機能 (New!)
- **統合ダッシュボード**: GUI上で、主要KPI、技術成熟度、技術進化推移、WIPヒートマップ、リードタイム分布、ゲート待ち時間を一括表示。
- **スクロール表示**: 豊富なグラフを整理して表示するため、スライダーによるスクロール可能な可視化エリアを実装。
- **詳細レポート**: Matplotlib/Seaborn を用いた高品質なレポート画像を `reports/viz/` に自動生成可能。
- **KPI比較**: シナリオ間の利得（Gain）や完了ジョブ数の相関を散布図で表示。

### 3. 多層的な承認プロセスとリワーク
- **DRゲート**: 周期的な開催と承認者（Senior等）の能力（スキル・キャパシティ・品質）を考慮。
- **リワークループ**: 承認失敗時の再試行（不確実性の再燃）と、知識減衰（Decay）による手戻り。

### 3. 組織・エージェント・デジタルツイン (Plan 5x由来)
- **学習・スキル**: エージェントが実験を重ねることでスキルが向上。
- **組織間通信**: チーム間の情報の欠落・歪みをシミュレート。技術の暗黙知度（Tacitness）が高いほど、通信による情報劣化が深刻化するロジックを搭載。
- **デジタルツイン**: `past_logs.csv` から過去の実績値を読み込み、シミュレーション上の能力値をキャリブレーション。

## 実行方法

### 1. インタラクティブ・ダッシュボード (GUI) - **推奨**
Plan 6の全パラメータをGUI上で調整し、リアルタイムに経営KPIと技術成熟度を確認できます。
```bash
python3 gui_sim.py
```
- **入力**: タブ形式の設定パネルで、プロジェクト、リソース、技術閾値、通信品質などを詳細に設定。
- **DOE一括実行**: パラメータを自動で振りながら複数回シミュレーションを実行し、結果を `reports/batch_results.csv` に保存。
- **詳細レポート出力**: シミュレーション終了後に `reports/viz/` へ各シナリオの可視化グラフを一括生成。
- **ダッシュボード**: 累計Gain、完了ジョブ数、DRコスト、および各技術要素の成熟度/不確実性をグラフ表示。

### 2. CLI実行 (非推奨)
`run_sim.py` によるCLI実行は現在非推奨となっており、すべての機能は `gui_sim.py` に統合されました。詳細は [GUI機能統合および run_sim.py 停止・削除プラン](Migration_Plan_GUI_Unification.md) を参照してください。

## 主要ディレクトリ構成
- `core/`: 統合シミュレーションコア（Hybrid Engine, ScenarioManager, Gates, etc.）
- `configs/`: 設定ファイル（`custom_flow.json`, `past_logs.csv`）
- `reports/`: 実行結果（CSV, PNG）
- `docs/`: ドキュメント（ガイド、改善プラン、技術レポート）
- `analysis/`: 可視化・メトリクス計算ロジック
- `runner/`: フロー構築用アダプター

## モデルの示唆
Plan 6では、「リソース（エンジニア）を増やして実験回数を稼ぐ」ことと、「DRゲートを厳格に運用して品質を保つ」こと、さらに「組織間の通信を円滑にして手戻りを防ぐ」ことのトレードオフを定量的に評価することが可能です。
